# Stakeholder Register — Acceptance Checklist

- [ ] The project charter was used as the primary input; any available concept memo was also reviewed.
- [ ] At least one structured brainstorming strategy (`brainstorming-role-playing` or `brainstorming-six-thinking-hats`) was applied to identify stakeholders rather than relying on an ad hoc list.
- [ ] Every stakeholder row in the inventory table is complete: name/role, organization, interest level, influence level, attitude, communication channel, cadence, and relationship owner are all filled.
- [ ] No placeholder rows remain in the inventory table.
- [ ] Every stakeholder has been assigned to exactly one quadrant of the engagement grid (Manage Closely / Keep Satisfied / Keep Informed / Monitor).
- [ ] The engagement grid groupings are consistent with the influence and interest levels recorded in the inventory table.
- [ ] Any stakeholder whose attitude is Unknown has an open question entry noting the plan to resolve it.
- [ ] The output cites the canonical stakeholder analysis reference URL (`https://en.wikipedia.org/wiki/Stakeholder_analysis`).
- [ ] The "Source consulted" section records which mode was used (offline or online) and does not include fabricated quotations or page numbers.
- [ ] The facilitation dialogue is in the language at `language.communication`, and the saved artifact is in the language at `language.output` (falling back to `language.communication` if `language.output` is absent or empty).
- [ ] The artifact is saved to `docs/pm-kit/outputs/stakeholder-register/<slug>.md` and begins with the three-line provenance header.

> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.
