Часть 1. SEO-аудит (09.10.2026)

Дата: 09.10.2026 · Рынок: Россия (Яндекс + Google) · Сайт: Next.js, 26 URL в sitemap, ~50 статей в блоге, 14 товаров

Краткий обзор

Что хорошо

  • Техническая база в порядке. HTTPS с HSTS, http → https через 301, gzip, серверный рендеринг: текст страниц сразу в HTML и виден роботам.
  • robots.txt настроен грамотно. Корзина, профиль, поиск и API закрыты, sitemap указан, AI-боты (GPTBot, ClaudeBot, Perplexity) открыты.
  • Метатеги заполнены везде. У всех страниц уникальные title и description, есть canonical. URL с utm склеиваются canonical'ом с чистым адресом.
  • Карточки товаров сильные. Объёмные страницы (на части карточек 1 500–2 500 слов вместе с отзывами), описания, характеристики, видео, инструкции, отзывы с маркетплейсов. Есть микроразметка Product + Offer (цена, наличие, SKU) и хлебные крошки.
  • Блог уже есть, и он большой. Около 50 статей под информационные запросы («как выбрать паровую швабру», «аэрогриль или духовка» и т.д.) с разметкой Article, FAQ и хлебных крошек.
  • Сильные коммерческие факторы для Яндекса. Есть страницы доставки, гарантии, возврата и оферты, контакты с реквизитами юрлица, поддержка в Telegram/MAX.
  • Картинки отдаются в современных форматах (WebP/AVIF через next/image).

Что плохо

  • Сайт генерирует бесконечные дубли. Любой несуществующий адрес отдаёт 200 вместо 404, а /blog/<что угодно> ещё и открыт к индексации с canonical на самого себя.
  • Блог не участвует в поиске так, как мог бы:
    • ни одной статьи нет в sitemap;
    • на товары ссылаются только 3 статьи из 50;
    • 6 пар статей дублируют друг друга по теме и конкурируют между собой в выдаче.
  • Нет категорийных страниц под коммерческий спрос. Например, у запроса «вертикальный моющий пылесос» около 190 тыс. показов в месяц, но сайту нечего показать по нему, кроме одной карточки.
  • Ошибки в структуре заголовков на всех страницах:
    • H1 главной — «— Готовка с радостью»;
    • первый H2 на каждой странице — «Сравнение разных категорий невозможно» (текст скрытого окна);
    • у страницы /blog вместо своего H1 — заголовок одной из статей.
  • Около 90% картинок без alt: 3 674 из 4 076.
  • Тяжёлые карточки товаров. HTML до 490 КБ, до 275 картинок грузятся без lazy-load.
  • Ошибки в sitemap. В нём нет блога и товара CremaX.
  • Сервер периодически обрывает соединение. В наших замерах это 1–2 запроса из 10, на любых страницах, включая главную.
  • Нет SSL-сертификата на www.luxhomme.store. Пользователь, набравший адрес с www, видит ошибку.
  • По брендовым товарным запросам сайт не виден: выдачу забирают Яндекс Маркет, М.Видео и карточка в Яндекс Картах.

Что не удалось проверить

  • Core Web Vitals (скорость). PageSpeed API упёрся в лимит, браузерный замер из этой среды не прошёл. Нужны данные из PageSpeed Insights или Яндекс Вебмастера / Search Console.
  • Индексация и позиции. Нужен доступ к Яндекс Вебмастеру и Google Search Console.
  • Метрика. Счётчик в исходном HTML не найден. Возможно, он грузится после согласия на cookie, но это нужно проверить.

Где alt теряется: медиатека или код витрины

Витрина на Next.js берёт alt из медиатеки WP не везде. В части блоков alt пустой, даже если в WP он заполнен; в других витрина подставляет свой текст.

Вывод

  1. Заполнение alt в медиатеке WP напрямую исправит только тексты статей. Для галереи товаров (главное фото + миниатюры, 114 файлов) это нужно проверить на одной картинке: сейчас там нет ни одного файла с alt в WP, поэтому неизвестно, берёт ли его витрина.
  2. Самые массовые пустые alt — фото из отзывов (444 файла) и слайды описания. Их правильнее закрыть шаблоном в коде витрины, а не вручную.
  3. Пять блоков витрины (слайды описания, «Читайте также», обложка статьи, большая карточка блога, похожие товары) игнорируют alt из WP — это задача разработчику Next.js.

Часть 3. Мета-теги (13.10.2026)

Дата: 13.10.2026 · Дополнение к разделу 3 SEO-аудита (seo-audit-2026-10.md). Alt — отдельно в alt-audit-2026-10.md.

Источники: обход 84 страниц (sitemap + каталог + блог + 57 статей + 15 товаров), REST API WordPress (Yoast) — только чтение.

Главное

Витрина не берёт мета-теги из Yoast. Title и description генерирует код Next.js:

  • товары: title = «Купить {название} — {цена} | Luxhommè», description = та же фраза + начало описания товара, обрезанное по символам;
  • статьи: title = заголовок записи + «| Luxhommè», description = анонс записи.

Description в Yoast заполнен у 32 из 57 статей — на сайте не совпадает ни один. У товаров то же (проверено на AirChef: в Yoast своё описание, на сайте — шаблон). Правка мета-тегов в Yoast на сайт не повлияет, пока разработчик не подключит поля Yoast (yoast_head_json) к generateMetadata в Next.js.
