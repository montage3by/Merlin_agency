# Автоматические письма: сайт на WordPress → Битрикс24

Цель: человек делает действие на сайте (оформил заказ, зарегистрировался, заказ передан в доставку) — Битрикс24 сам отправляет ему нужное письмо.

Портал: `b24-nb2uoy.bitrix24.ru`. Сайт: WordPress + WooCommerce (заказы, купоны, покупатели), витрина на Next.js. Названия пунктов меню Битрикс24 в разных версиях отличаются — ориентир по смыслу.

## Как это работает

```
Сайт (WooCommerce)            Битрикс24
──────────────────            ─────────────────────────────────────
событие на сайте   ──────►   контакт (email, имя, телефон, промокод)
                             сделка в воронке «Заказы с сайта»
                             стадия сделки = статус заказа
                                    │
                                    ▼
                             робот на стадии → письмо клиенту
```

Сайт ничего не отправляет сам — он только передаёт в Битрикс24 данные и меняет стадию сделки. Письма шлют роботы Битрикс24: каждая стадия = своё письмо.

## Шаг 0. Решить до начала

1. **Кто отправляет служебные письма.** WooCommerce уже умеет слать «Заказ принят», «Заказ выполнен». Если письма будет слать Битрикс24, эти письма в WooCommerce нужно выключить, иначе клиент получит два одинаковых: WordPress → WooCommerce → Настройки → **Email’ы** → открыть письмо → снять «Включить это уведомление».
2. **Согласие на рекламу.** Служебные письма (заказ принят, передан в доставку) можно слать всем. Рекламные (промокод, распродажа, «вернитесь в корзину») — только тем, кто дал согласие (ст. 18 закона «О рекламе»). Нужна галочка «Хочу получать акции» при регистрации/заказе, и её значение передаётся в Битрикс24.
3. **Почта отправителя.** Адрес на домене `luxhomme.store` (например, `care@luxhomme.store`), для домена настроены SPF и DKIM — иначе письма уйдут в спам.
4. **Тариф Битрикс24.** Роботы, вебхуки и отправка писем из CRM доступны не на всех тарифах — проверить в «Мой тариф».

## Шаг 1. Подготовить Битрикс24

### 1.1. Воронка «Заказы с сайта»
CRM → Сделки → настройка воронок → **Создать воронку** «Заказы с сайта». Стадии = статусы заказа в WooCommerce:

| Статус WooCommerce | Стадия в Битрикс24 | Письмо клиенту |
|---|---|---|
| Ожидает оплаты (pending) | Новый заказ | «Заказ принят, ждём оплату» |
| В обработке (processing) | Оплачен / собираем | «Заказ оплачен, собираем» |
| На удержании (on-hold) | Ждёт подтверждения | «Менеджер свяжется для подтверждения» |
| Выполнен (completed) | Выполнен | «Спасибо за покупку» + через N дней «Оставьте отзыв» |
| Отменён (cancelled) | Отменён | «Заказ отменён» |
| Возвращён (refunded) | Возврат | «Деньги возвращены» |

Сверить список статусов с вашим WooCommerce: WooCommerce → Заказы → фильтр по статусам. Если есть свои статусы (например, «Передан в доставку»), добавить для них стадии.

### 1.2. Поля
CRM → Настройки → Пользовательские поля.
- **Сделка:** «Номер заказа на сайте», «Состав заказа» (строка), «Ссылка на заказ», «Промокод в заказе».
- **Контакт:** «Согласие на рассылку» (да/нет), «Персональный промокод», «Источник» (сайт).

### 1.3. Шаблоны писем
Для каждой строки таблицы из 1.1 — шаблон письма. В тексте используются поля CRM: имя контакта, номер заказа, сумма, промокод. Вставляются кнопкой выбора полей в редакторе письма (вид `{=Document:...}`).

### 1.4. Роботы
Сделки → воронка «Заказы с сайта» → **Роботы** (Автоматизация). На каждую стадию → **Добавить робота** → «Отправить письмо» (клиенту):
- Кому: контакт сделки (email).
- От кого: адрес на `luxhomme.store`.
- Текст: шаблон из 1.3.
- Когда: «Сразу» (для «Выполнен → отзыв» — с задержкой, например через 7 дней после перехода на стадию).
- Условие для рекламных писем: поле «Согласие на рассылку» = да.

## Шаг 2. Связать сайт с Битрикс24 — выбрать один способ

| Способ | Кто делает | Срок | Плюсы | Минусы |
|---|---|---|---|---|
| **A. Готовый плагин-коннектор** WooCommerce ↔ Битрикс24 | Вы / администратор сайта | 1 день | Без кода, обычно умеет заказы, статусы, контакты | Платный; проверить, что работает с вашей версией WooCommerce и заказами, которые создаёт витрина на Next.js |
| **B. Сервис-посредник** (Albato, ApiX-Drive и аналоги) | Вы | 1–2 дня | Без кода, наглядные связки «событие → действие» | Абонентская плата; задержка 1–15 минут в зависимости от тарифа сервиса |
| **C. Свой код** (входящий вебхук Битрикс24 + хуки WordPress) | Разработчик сайта | 1–3 дня | Бесплатно, мгновенно, полный контроль: промокоды, корзины, любые события | Нужен разработчик и поддержка |

Рекомендация: если разработчик сайта на связи — **C** (код ниже, файл `luxhomme-b24.php`). Если нужно быстро и без разработчика — **B**.

Плагины и сервисы искать по запросу «WooCommerce Битрикс24» в каталоге плагинов WordPress, в Маркете Битрикс24 и на сайтах сервисов. Перед оплатой проверить на тестовом заказе: создаётся ли контакт без дублей по email, создаётся ли сделка, меняется ли стадия при смене статуса.

### Для способов B и C: входящий вебхук Битрикс24
Битрикс24 → **Разработчикам** (или Приложения → Вебхуки) → **Входящий вебхук** → права: **CRM** → Сохранить. Получится адрес вида `https://b24-nb2uoy.bitrix24.ru/rest/1/xxxxxxxx/`. Это ключ доступа к CRM — **не пересылать в чатах и почте**, передавать разработчику/вставлять в сервис напрямую.

## Шаг 3. Сценарии

| # | Действие на сайте | Что происходит в Битрикс24 | Письмо | Тип |
|---|---|---|---|---|
| 1 | Оформил заказ | Контакт (найти по email или создать) + сделка «Новый заказ» | «Заказ №… принят» | служебное |
| 2 | Статус заказа сменился | Сделка переходит на соответствующую стадию | письмо стадии (таблица 1.1) | служебное |
| 3 | Заказ выполнен | Стадия «Выполнен», робот с задержкой 7 дней | «Как вам покупка? Оставьте отзыв» | служебное |
| 4 | Зарегистрировался / подписался (с согласием) | Контакт + персональный промокод в поле контакта | «Ваш промокод −N%» | рекламное |
| 5 | Положил в корзину и не купил | Сделка «Брошенная корзина» | «Вы кое-что забыли» | рекламное, нужна доработка витрины |

### Как сделать персональный промокод (сценарий 4)
1. Сайт при регистрации создаёт купон в WooCommerce: одноразовый, привязан к email покупателя («Ограничение по email»), со сроком действия.
2. Код купона записывается в поле контакта «Персональный промокод» в Битрикс24.
3. Робот / приветственное письмо подставляет это поле в текст.

Шаги 1–2 делает код (способ C) или сервис-посредник, если умеет создавать купоны WooCommerce.

### Брошенная корзина (сценарий 5)
Корзина живёт на витрине Next.js и до оформления заказа в WooCommerce не попадает. Нужна доработка витрины: при добавлении в корзину у вошедшего пользователя отправлять событие в Битрикс24 (или в WordPress), а если заказа нет 2–3 часа — сделка «Брошенная корзина» и письмо. Делать после сценариев 1–4.

## Шаг 4. Проверка перед запуском

- [ ] Тестовый заказ на свой email: в Битрикс24 появились контакт и сделка, пришло одно письмо (не два).
- [ ] Повторный заказ с тем же email — новый контакт не создаётся, сделка привязывается к старому.
- [ ] Смена статуса в WooCommerce → стадия сделки → письмо стадии.
- [ ] Отмена заказа → стадия «Отменён», письмо об отмене.
- [ ] Регистрация с согласием → промокод в контакте и в письме; без согласия — рекламное письмо не уходит.
- [ ] Письма не в спаме (Gmail, Яндекс, Mail.ru); ссылки ведут на сайт, отписка работает.
- [ ] Письма WooCommerce, которые дублируют Битрикс24, выключены.

## Для разработчика (способ C)

Файл `luxhomme-b24.php` — mu-plugin для WordPress: кладётся в `wp-content/mu-plugins/`. Адрес вебхука — в `wp-config.php`:

```php
define('LUX_B24_WEBHOOK', 'https://b24-nb2uoy.bitrix24.ru/rest/1/xxxxxxxx/');
define('LUX_B24_DEAL_CATEGORY', 0); // ID воронки «Заказы с сайта»
```

Что делает:
- новый заказ (в том числе созданный витриной через REST API) → найти/создать контакт по email → сделка в воронке со стадией по статусу; ID сделки сохраняется в заказ;
- смена статуса заказа → смена стадии сделки;
- регистрация покупателя → контакт + одноразовый купон WooCommerce, код в поле контакта.

Перед запуском: заполнить в коде коды стадий воронки (`C{ID}:NEW` и т. д. — видны в Битрикс24 через REST `crm.dealcategory.stage.list`) и коды пользовательских полей (`UF_CRM_...`), проверить на тестовом портале или тестовой воронке.
