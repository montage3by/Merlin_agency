# Project Charter — Acceptance Checklist

- [ ] The project title, unique identifier, sponsor role, document version, and date are all present and populated (no `TBD` values).
- [ ] The strategic-alignment section names a specific organizational goal, portfolio objective, or strategic theme that the project advances.
- [ ] The purpose-and-justification section answers both "why this" and "why now" in full sentences.
- [ ] Every high-level objective is SMART-shaped (Specific, Measurable, Achievable, Relevant, Time-bounded).
- [ ] Success metrics are quantitative: each metric has a numeric target and a stated measurement method.
- [ ] Both in-scope and out-of-scope lists are populated; the out-of-scope list is not empty.
- [ ] Key milestones have target dates, and any tentative date is marked `(placeholder)`.
- [ ] The preliminary risk summary contains exactly three risks, each with a probability-impact characterization and a one-line mitigation.
- [ ] The authority-and-approvals block names the sponsor and project manager and includes signature and date slots for each approver.
- [ ] The output cites the canonical project-charter reference URL (`https://www.pmi.org/-/media/pmi/documents/public/pdf/pmbok-standards/12-project-management-principles.pdf`) and records whether offline or online mode was used without fabricated quotations or page numbers.
- [ ] The facilitation dialogue is in the language at `language.communication`, and the saved artifact is in the language at `language.output` (falling back to `language.communication` if `language.output` is absent or empty).
- [ ] The artifact is saved to `docs/pm-kit/outputs/charter/<slug>.md` and begins with the three-line provenance header.

> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.
