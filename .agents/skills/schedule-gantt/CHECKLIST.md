# Schedule Baseline — Acceptance Checklist

- [ ] The Mermaid `gantt` block is syntactically valid and renders without errors in the team's chosen Markdown renderer.
- [ ] Every task in the WBS appears in the Gantt diagram with a unique task ID.
- [ ] All task dependencies are represented accurately — no dependency is omitted or misstated.
- [ ] The critical path is identified and the critical-path length matches the total project duration.
- [ ] At least two key milestones appear in the schedule summary table.
- [ ] The task-detail table records start date, end date, duration, owner, and dependencies for every task.
- [ ] The schedule assumptions are explicit and the project team has reviewed them.
- [ ] At least two schedule risks are documented with probability, impact, and mitigation.
- [ ] The artifact cites the canonical Gantt reference URL (`https://en.wikipedia.org/wiki/Gantt_chart`).
- [ ] The "Source consulted" section records which mode was used (offline or online) and does not include fabricated quotations or page numbers.
- [ ] The facilitation dialogue is in the language at `language.communication`, and the saved artifact is in the language at `language.output` (falling back to `language.communication` if `language.output` is absent or empty).
- [ ] The artifact is saved to `docs/pm-kit/outputs/schedule-gantt/<slug>.md` and begins with the three-line provenance header.

> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.
