# Epic and Story Breakdown — Acceptance Checklist

- [ ] Every Epic has a clear name, description of what it delivers and to whom, and stated success metrics.
- [ ] Every User Story follows the format "As a `<user type>`, I want `<action>`, so that `<outcome>`" with no fields omitted.
- [ ] Every story satisfies INVEST: it is independently deliverable, negotiable, valuable, estimable, appropriately sized, and testable.
- [ ] Each story has at least two acceptance criteria in Given / When / Then notation, each independently verifiable.
- [ ] Every story is assigned a priority of Must, Should, or Could; the rationale for Must stories is evident from the PRD.
- [ ] Dependencies between stories are recorded by story ID; there are no undeclared blocking relationships.
- [ ] The Backlog Summary section reports total epics, total stories, priority distribution, and an aggregate estimate (or a noted placeholder pointing to the cost-estimation skill).
- [ ] The output cites the canonical user-story reference URL (`https://www.agilealliance.org/glossary/user-story`).
- [ ] The "Source consulted" section records which mode was used (offline or online) and contains no fabricated quotations or page numbers.
- [ ] The facilitation dialogue is in the language at `language.communication`, and the saved artifact is in the language at `language.output` (falling back to `language.communication` if `language.output` is absent or empty).
- [ ] The artifact is saved to `docs/pm-kit/outputs/epics-and-stories/<slug>.md` and begins with the three-line provenance header.

> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.
