# Resource Plan — Acceptance Checklist

- [ ] Every role required by the project appears in the team roster with allocation percentage, start week, and end week.
- [ ] Each roster entry identifies either a named person or "TBD" — no role is left entirely unspecified.
- [ ] All significant equipment and infrastructure items are listed with estimated cost and recurrence.
- [ ] The budget summary includes all four categories: people, tools/software, travel/expenses, and contingency reserve.
- [ ] Every external vendor or shared-team dependency is listed with the service provided, when it is needed, and the current agreement status.
- [ ] Every "TBD" role in the roster has a corresponding entry in the hiring and onboarding timeline with a target date and a named hiring owner.
- [ ] The assumptions section states all material assumptions about availability, rates, and shared resources.
- [ ] The artifact cites the canonical resource-management reference URL (`https://en.wikipedia.org/wiki/Resource_management`).
- [ ] The "Source consulted" section records which mode was used (offline or online) and does not include fabricated quotations or page numbers.
- [ ] The facilitation dialogue is in the language at `language.communication`, and the saved artifact is in the language at `language.output` (falling back to `language.communication` if `language.output` is absent or empty).
- [ ] The artifact is saved to `docs/pm-kit/outputs/resource-plan/<slug>.md` and begins with the three-line provenance header.

> Mark **PASS** or **FAIL**. On **FAIL**, return to the skill with notes.
