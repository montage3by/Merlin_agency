Все три в «Избранных». По UTM смотреть: Отчёты → Источники → Метки UTM, цель main.

### Ограничения (по коду витрины, 27.11)

- События уходят в Метрику, только если посетитель принял аналитические cookie (баннер cookie). Без согласия цели не срабатывают: данные неполные.
- `begin_checkout` не отправляется, если после оформления сайт ведёт сразу на внутреннюю страницу подтверждения (похоже, оплата по счёту). Такие заказы не попадут в «Заказ создан».
- `purchase` для оплаты по счёту (flow invoice) отправляется на странице успеха, хотя счёт может быть ещё не оплачен.
- В `purchase` нет суммы заказа: доход по цели «Заказ оплачен» будет 0.

### Что попросить у разработчика

1. В `begin_checkout` и `purchase` передавать `order_price` и `currency: "RUB"` (и номер заказа): тогда у целей будет доход.
2. Отдельное событие для заказа с оплатой по счёту (например, `order_created_invoice`), а `purchase` только после фактической оплаты.
3. Надёжнее всего статус «оплачен» брать из CRM: у счётчика уже есть CRM-цели (`cdp_order_*`), но данные заказов в Метрику не загружаются (0 срабатываний за 30 дней).
